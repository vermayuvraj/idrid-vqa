## Project

**IDRiD-VQA — Fine-Tuning Qwen2-VL-2B for Explainable Diabetic Retinopathy Grading on Consumer Hardware.**

Fine-tune `Qwen/Qwen2-VL-2B-Instruct` with QLoRA + Unsloth on the IDRiD dataset to build a medical VLM that (a) grades diabetic-retinopathy severity 0–4 and (b) generates structured clinical explanations. Deliverables: model weights + `IDRiD-VQA` dataset on HuggingFace, and an arXiv paper (target Sept 2026), then a MICCAI 2027 workshop submission.

## Hardware constraints (NEVER violate)

- GPU: NVIDIA RTX 4050, **6 GB VRAM** (6141 MiB). All training/inference must fit in **≤ 5.5 GB VRAM**.
- CPU: Intel i7 HX. OS: Windows 11 + **WSL2 Ubuntu** (all Python/CUDA runs in WSL2).
- Mandatory training config: `load_in_4bit=True`, `use_gradient_checkpointing="unsloth"`, `per_device_train_batch_size=1`, `gradient_accumulation_steps=8`, `max_seq_length=1024`.
- **Never use float32.** Use **bfloat16** or **4-bit** only.

## Model

- `Qwen/Qwen2-VL-2B-Instruct` via **Unsloth `FastVisionModel`**.
- QLoRA: `r=16`, `lora_alpha=16`, target **all attention + MLP** projection layers, `lora_dropout=0`, `bias="none"`.
- Framework: Unsloth + HuggingFace **TRL `SFTTrainer`** (vision).

## Dataset

**IDRiD** (Indian Diabetic Retinopathy Image Dataset), 516 fundus JPEGs.
- DR grade: 0 No DR, 1 Mild, 2 Moderate, 3 Severe, 4 Proliferative.
- Lesion masks: MA (microaneurysms), HE (hemorrhages), EX (hard exudates), SE (soft exudates).
- Source: https://ieee-dataport.org/open-access/indian-diabetic-retinopathy-image-dataset-idrid
- **Official split (canonical): train = 413 images, test = 103 images.** The data
  ships pre-split into Training/Testing folders and train+test *reuse the same
  filenames* (both have `IDRiD_001`), so the split is tracked by folder, never by
  index. (This supersedes the original brief's "first 416 / last 100" — 413/103 is
  the standard IDRiD split and is what the paper/benchmarks use.)
- Normalised layout (produced by `scripts/organize_data.py` from the extracted zips):
  - `data/raw/images/train/IDRiD_001.jpg … IDRiD_413.jpg`
  - `data/raw/images/test/IDRiD_001.jpg … IDRiD_103.jpg`
  - `data/raw/labels/{train,test}.csv` — `Image name, Retinopathy grade, Risk of macular edema`
  - `data/raw/_staging/` — raw extracted zips incl. the segmentation subset (optional)
- **Lesion masks are TIF and belong to a separate 81-image segmentation subset**
  with different numbering; they do **not** map onto the 516 grading images. Lesion
  flags for the grading set therefore come from **grade-conditioned clinical priors**
  (`lesion_source="grade_prior"` in the manifest), which avoids the train/test
  filename-collision that reusing masks across splits would cause.

### Synthetic QA (IDRiD-VQA)
- ~2000 clinical QA pairs (4 per image), generated by **Gemini Flash**
  (`gemini-2.5-flash-lite` — 1.5 is retired and 2.5-flash's free-tier daily quota is
  tiny; flash-lite has a separate, larger free bucket. Override with `GEMINI_MODEL`)
  via `GEMINI_API_KEY`, **from the labels/lesion flags, not from pixels**.
- Generation is **batched** (8 images/call, ~65 calls), **throttled** (`GEMINI_MIN_INTERVAL`,
  default 4s) to respect the free-tier ~20 req/min limit, saved **incrementally**, and
  **falls back to deterministic templates** per-image if the quota is exhausted. Each QA
  pair records `qa_source` = `gemini` | `template`.
- 4 pair types per image: grade identification, lesion identification, clinical reasoning, patient recommendation.
- Save to `data/processed/idrid_vqa.json`.
- Record format:
  ```json
  {"image": "path",
   "conversations": [
     {"role": "user", "content": "<image>\nQuestion"},
     {"role": "assistant", "content": "Answer"}]}
  ```

## Environment gotchas & fixes (2026 stack — all pinned in requirements.lock.txt)
The Unsloth 2025.5.1 + transformers 4.51.3 + Qwen2-VL vision path needed six fixes to
train a single step on this box; all are baked into the code / lockfile:
1. **`trl==0.15.2`** — the resolver's default (0.11.4) breaks unsloth_zoo's GKD-trainer
   patcher on import (`parameter without a default follows parameter with a default`).
2. **`accelerate==1.7.0`** — 1.14.0's `prepare` references `FP8BackendType`, which
   unsloth_zoo's source-patcher doesn't carry into scope (`NameError`).
3. **Training data is a plain `list`, not a HF `Dataset`** — `Dataset.from_list` Arrow-
   encodes nested PIL images to `{"bytes","path"}` dicts, which Unsloth's vision collator
   can't read (`'dict' has no attribute 'startswith'`). `src/train.py:load_train_dataset`.
4. **`torch.compile` disabled** (`TORCHDYNAMO_DISABLE=1`, set at the top of train/eval/demo)
   — inductor needs a system C compiler; WSL has none and `sudo apt` needs a password.
   Unsloth's Triton kernels compile via their own LLVM, so this only loses inductor fusion.
5. **`trainer.model_accepts_loss_kwargs=False` + patched Qwen2-VL forward** — Unsloth's
   grad-accum fix injects `num_items_in_batch` into a forward that (in 4.51.3) rejects it.
   `src/train.py:_patch_num_items_in_batch` drops the kwarg.
6. **Gemini model cycling** — free-tier quota is per-model and small (~48 imgs/bucket);
   `dataset.py` batches 8 imgs/call, throttles, and cycles a model pool
   (`gemini-flash-latest` → `gemini-3.1-flash-lite` → ...) to reach full Gemini coverage,
   with a resumable template fallback. Result: 2064/2064 pairs Gemini-sourced.
